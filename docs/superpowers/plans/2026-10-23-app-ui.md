# Application UI Implementation Plan

> Execute the approved app-wide scope with a shared foundation and isolated route migrations.

**Goal:** Simplify every live application journey in a coherent reference-led visual system.
**Architecture:** Preserve React/Next data and transaction boundaries. Share CSS tokens and accessible interaction primitives; migrate page-specific layouts.
**Tech Stack:** Next 16, React 19, TypeScript, CSS, existing wagmi integrations.
**Spec:** ../specs/2026-10-23-app-ui-design.md

## Global constraints
- Application only; preserve landing page, real financial data, APIs, contract calls and explicit wallet signatures.
- Keyboard access, all five mobile destinations, reduced motion, readable numeric and failure states.
- No fake connection verification, return figures, or transaction success.

## Tasks
- [x] Shared foundation: `fe/src/components/ui/`, application stylesheet, app shell and wallet dialog. Focus management, consistent buttons/states, responsive navigation.
- [x] Agents and settings: route-local components/styles, guided client setup, clear permission editing and categorized settings, persistent feedback.
- [x] Transaction surfaces: basket creation, allocation editor and action drawers; shared visual structure and distinct pending states.
- [x] Portfolio, baskets, activity and borrowing: hierarchy, meaningful empty/error states, responsive data presentation.
- [x] Verification: TypeScript, existing relevant tests, build, desktop/mobile browser flows, mechanical design detector, independent finish review; document final system.

## Review focus
Disconnected/restoring wallets; failed data fetches mistaken for zero; pending wallet requests; long asset names and addresses; mobile overflow and dialog focus.

## Execution record
Existing isolated Superset worktree verified. User approved app-wide implementation. Code-led path chosen because the reference establishes material while live financial interaction determines layout. No additional concept approval required. Independent route migrations may proceed in parallel under dispatching-parallel-agents; shared files remain root-owned.
