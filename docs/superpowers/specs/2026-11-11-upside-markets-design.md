# Stock Upside Markets: product and technical design

**Status:** implementation handoff, 11 November 2026. Read with [the execution plan](../plans/2026-11-11-upside-markets.md). This is a **new product**, separate from Risk Split and baskets. The [interactive HTML concept](../../../.codex-visuals/stock-upside-marketplace.html) is an approximate layout and journey template, not a pixel-perfect design specification. Every quote, balance and chart in it is fictional. Ship the public and admin interfaces with Othelio's existing colors, typography, spacing, surfaces and AppShell conventions.

## Decisions and sequence

1. Finish, test, document, commit and push the existing `feature/risk-split` work to GitHub **before any Upside implementation**. Include the public Base deployment manifest and pins; exclude keystores, caches, credentials and generated build state. Preserve the original Risk Split contracts, indexer, backend, admin tools and direct URLs. Record its actual formula and operational limitations in `docs/risksplit/original-v1.md`. Do not silently rewrite its deployed payoff.
2. Start a separate Upside feature branch after that pushed checkpoint. Keep Risk Split visible in public navigation alongside Upside by default. `NEXT_PUBLIC_RISK_SPLIT_NAV_ENABLED=false` may hide only its navigation item later; direct routes, backend APIs and admin operations remain available. Do not change V1 contract pins or database meaning. Keep the legacy Risk Split indexer switch enabled by default, with an honest paused/stale status when it is disabled.
3. First release: **continuous Upside + Residual**, not the fixed-dollar prediction ticket proposed during ideation. The buyer buys gains above a strike until a fixed expiry; the stockholder keeps the remaining stock value and any sale premium. The latter claim is called **Residual**, never “Protected.”
4. A weekly round groups one underlying, one approved expiry, a verified starting reference and target suggestions. Multiple expiries for the same asset may coexist. No one-active-expiry constraint is imposed. Only the owner may create a round or strike market. The owner always approves expiries, feeds, assets, and strike limits.
5. **Supported underlyings are exactly the Othelio basket registry's supported tokens for that chain.** Use `OthelioAssetRegistry.getSupportedTokens(chainId)` for discovery and `getAsset(chainId,token)`/`isSupported` for onchain validation. Do not build a second Upside asset allowlist or silently substitute the static `TOKEN_FEED_REGISTRY` catalog. Product-specific compatibility failures are explicit disabled reasons, not a hidden alternative list.

## Payoff, custody and units

For one underlying token unit, strike `K` and positive expiry fixing `S`, the **economic values** are:

`Upside(S) = max(S − K, 0)`; `Residual(S) = min(S, K)`; `Upside(S) + Residual(S) = S`.

For example, `K=$205`, `S=$230`: Upside is worth $25 and Residual $205. One pair redeems to exactly one underlying token before settlement. After settlement the Upside holder receives `25/230` underlying token and the Residual holder `205/230`, subject only to integer rounding. A buyer's net profit at expiry is payoff less premium and fees; the premium is an order-book price, never calculated from the oracle alone. A `0.4` exposure multiplies all values by `0.4`.

Contract storage uses the registry feed's decimal scale for `K` and `S` and the underlying's actual decimals for claim units; USDC amounts use six decimals. The registry supports token/feed decimals up to 38, so either support each registered decimal format correctly (including whole-unit 0-decimal assets) or return a specific compatibility failure for that asset rather than quietly omitting it. Validate registry decimals against actual token/feed reads; reject fee-on-transfer/rebasing semantics unless explicitly reviewed. Validate token transfer eligibility, issuer redemption rules and share-to-token ratio/corporate-action behavior before launch. No promise of immediate cash: redemption is in underlying tokens. An optional USDC conversion is a separate executable quote.

Implement settlement as **allocations of actual collateral**, not independently rounded per-burn fractions. At fixing, snapshot raw collateral and equal claim supply `Q`. For `S>0`, `upsideAllocation = floor(collateral × max(S−K,0) / S)` with full-precision multiplication; `residualAllocation = collateral − upsideAllocation`. For `S=0`, assign raw collateral to Residual (economically zero at the fixing). Each side's redemption uses cumulative allocation: `out = floor(allocation × newRedeemed / Q) − floor(allocation × oldRedeemed / Q)`. This telescopes to the full allocation at the final redemption and cannot exceed collateral. Permit pair burn/stock withdrawal before settlement, including after expiry while unresolved; freeze new mint at expiry. After settlement, each side redeems separately; there is no admin withdrawal or unilateral dust sweep. Define any zero-supply settlement as a no-op allocation. Use `mulDiv`, checked arithmetic, reentrancy guard, exact inbound balance delta and strict token authorization.

## Weekly round and market policy

The new factory pins the existing `OthelioAssetRegistry` address immutably. The admin chooser reads its onchain `getSupportedTokens(block.chainid)` list. The admin records an approved `RoundConfig`: chain, underlying, the **registry's configured feed** and a compatible adapter, a specific feed reference round/price/time, round start, approved expiry inside the feed's regular trading session, expected move in the same price scale, provenance URI/hash, strike tick, allowed strike bounds. `registerRound` and `createMarket` re-read `isSupported` and `getAsset`, rejecting disabled assets and mismatched feed/decimals even for the owner. `mint` also refuses new exposure if the registry later disables an asset; pair withdrawal and claim redemption remain available. No second Upside asset allowlist exists. Only the owner may register or change **future** policy; economic terms of an active market never change. Store the exact config/version and emit events. Owner/deployer wallet signs transactions in the admin UI; no browser-stored key and no Safe dependency in this release.

Admin preview proposes four strikes from the frozen starting price `P0` and weekly expected move `M`: `P0 + {0, 0.5, 1, 2} × M`, each rounded to the approved strike tick (one USD for suitable launch stocks). UI labels: **Starting price, Reach, Strong move, Long shot**. Display the exact reference, absolute strike and expiry. Reject duplicate/zero strikes after rounding; do not quietly mislabel a low-priced asset. One-dollar ticks may need an asset eligibility floor or a later smaller-tick policy. `M` is an input for spacing, **not** the market premium or an oracle-published probability.

Prefer a same-expiry at-the-money options-implied volatility snapshot from a licensed market-data API. The backend computes `M ≈ P0 × sigma × sqrt(timeToExpiryYears)` and records source/time. A manually entered, sourced value is acceptable for the first launch; historical realized volatility is explicitly labelled a fallback and can miss earnings. The admin approves the finalized values. Onchain code does not claim to verify the offchain volatility source; it does verify the reference feed data and enforces the approved strike bounds and expiry. No quote/source means the admin cannot represent the estimate as live. The four preset targets are a launch UI choice; they are not a hard cap on future custom strikes.

Only the owner chooses and creates all strikes, normally the four presets, within the round's immutable strike min/max/tick and approved expiry/feed. Duplicate `(roundId,strike)` creation reverts. Users cannot create a new expiry or change `P0`/`M`. A market can exist with zero orders, but Explore promotes only executable, fresh quotes; the admin sees all markets. Multiple approved weekly rounds and expiries may coexist.

Expiry uses a named America/New_York calendar with holidays, early closes and feed cadence buffer in admin preview; the onchain factory only accepts owner-approved exact timestamps. Define the fixing as the last sufficiently fresh, valid observation at or before expiry. A delayed settlement cannot use a later price. The successor-round proof across Chainlink phases is a security gate; do not copy V1's adapter without independent review. Missing/stale/disputed fixing halts redemption until a separately reviewed recovery mechanism, never a silent next-day substitution.

## Market and UI behavior

The HTML concept is an approximate reference for information order and interactions. Apply Othelio's current app palette, typography, padding, spacing, surfaces, responsive grid and AppShell; do not copy the HTML's styles or sample data literally. `/app/upside` opens on square stock/market tiles and search. A tile displays stock, target, expiry, **best executable buy ask and size**, and **best executable sell bid and size**; absent quotes say “No offers”/“No bids.” The stock detail defaults to the current liquid weekly round, with an unobtrusive expiry selector when multiple exist. The target selector shows Starting price, Reach, Strong move, Long shot, actual dollar strikes and best rates. The detail retains the chart above the right Buy/Sell action panel, full bid/ask depth and a plainly distinguished stock-price chart. Market creation is available only in the owner admin workspace, separately from placing a premium order.

Buy/Sell tickets show cost/proceeds, exposure (fractional underlying units), average execution price across levels, max purchase loss, expiry breakeven `K + averagePremiumPerShare` for Upside buyers, and a three-scenario payout calculator. With `0.5 @ $4.10` plus `0.7 @ $4.20`, buying `1.2` costs `$4.99`, average `$4.1583` per share. Sell/list flow explains the surrendered gains above `K`; Residual **retains downside**. Positions aggregate across all stocks, strikes and expiries, with unknown cost basis displayed as unknown after transfers rather than fabricated. Search, order placement, cancel, stockholder mint/list, claim resale and redemption must work with real data. Limit orders can remain unfilled.

Use real chart history, never the synthetic `AssetDetailModal` fallback as market data. Expose source/as-of time and a stale/unavailable state. Indexer lag or failed onchain order verification removes “executable” pricing and prevents stale fill construction. Quote amounts are USDC per whole claim unit; balances and approvals are checked at posting and fill, with onchain status authoritative. Relay hide is distinct from onchain cancellation.

Use the existing 0x venue only after a Base fork confirms the deployed proxy supports `batchFillLimitOrders` for the exact claim/USDC pairs, partial amounts, all-or-revert execution and actual token permissions. A single buy may sweep several signed asks at best-price then time priority. Build an expiring quote for the requested size with exact order hashes/amounts, max total USDC and book sequence; simulate before wallet confirmation. `revertIfIncomplete=true` means a raced order reverts rather than silently buying fewer units at a worse average. If batch fill is unavailable, do not present the UX as one transaction: revise the venue design and security review before release. Trading across different strikes never pretends to be the same claim.

## Data flow and compatibility

New contracts live under `contracts/src/upside/`; new migrations, indexer state, backend module/routes and FE components are versioned under `upside`. Shared 0x encoding, decimals and wallet helpers can be extracted behind regression tests, but V1 endpoints/tables/ABI stay valid. Every API response includes `product=UPSIDE`, chain ID, round/series IDs, onchain addresses, decimal scales, as-of block and source/freshness. The Upside indexer starts at the new factory deployment block, handles replay/reorg and processes factory/round/market, mint, pair withdrawal, transfer, fixing, redemption and 0x fill/cancel events. Do not rely on local DB history or reset the existing persistent DB.

Add `RISK_SPLIT_INDEXING_ENABLED` to indexer config and examples. It defaults to `true` to preserve current V1 behavior; an explicit `false` skips Risk Split state loading, address filtering, log decoding, projections, reconciliation and Risk Split RPC work while baskets, prices and Upside continue. It never deletes existing Risk Split rows or rewinds the basket checkpoint. Record an independent last-indexed Risk Split block so re-enabling catches up from that block, including blocks scanned while disabled, with replay/reorg safety. Bootstrap that cursor from a provably processed V1 checkpoint; if none exists, replay idempotently from the pinned V1 factory deployment block rather than skipping uncertain history. Persist enabled/paused and progress so operations APIs and admin UI can show last indexed block and lag. Existing Risk Split direct pages must identify paused/stale indexed data; contract reads and withdrawals remain available.

`NEXT_PUBLIC_RISK_SPLIT_NAV_ENABLED` also defaults to `true`. It controls public navigation only, not route access or backend/indexer availability. Keep both switches explicitly `true` in the current Base development profile; when bringing Risk Split back after a pause, let indexing catch up and verify fresh backend data before promoting its navigation again.

The admin panel and `/v1/upside/assets` use the same onchain supported-token enumeration as basket onboarding. That endpoint returns every supported registry asset, with an explicit reason if an asset cannot yet be used for Upside; it does not substitute a second curated list. The public UI is not allowed to fabricate a market from a configuration that has not been created and indexed.

The admin portal is an operator workspace in Othelio's existing visual system. **Overview** shows actionable health: connected chain/owner, registry, indexer head/lag, Risk Split indexing enabled or paused, pending transactions and markets requiring settlement. **Assets** shows the basket registry list and eligibility reasons. **Rounds** gives a guided create flow: choose asset, verify feed/reference and market calendar, inspect expected-move source, preview exact expiry and four strikes, simulate, sign, then reconcile the receipt and indexed row. **Markets** lists all series, including empty, expired and settled ones, with strike, expiry, collateral, claim supply, best bid/ask, volume, fixing and redemption status; each detail has live book and event/transaction history. **Operations** exposes failed or lagging indexing, and recoverable actions with their exact onchain effects. Keep legacy Risk Split admin tools reachable and label their data stale if its indexer is off. Read-only inspection works without the owner wallet; write controls require the connected owner on the correct chain. Show transaction stages and actionable error text rather than generic fetch failures. Reuse existing components and tokens where possible; the HTML concept does not dictate admin layout.

## Launch gates and explicit limits

- Unit, fuzz, invariant, malicious-token and Base-fork tests prove payoff, token amounts, collateral conservation, role restrictions, expiry boundaries, fixing, decimals and rounding. Independently review new vault/factory/adapter plus batch-fill integration; no unresolved critical/high issues before meaningful mainnet exposure. Do not promise “zero bugs.”
- End-to-end on a pinned Base fork: admin configures two stocks and overlapping expiries; creates four strikes; non-owner creation fails; owner custom strikes within bounds work and out-of-bounds/duplicate/expiry change fails. Two makers quote a target, a taker buys across two levels in one tx, orders cancel, stockholder mints/lists, wallet positions reconcile, delayed fixing settles, both claims redeem, and all raw collateral is accounted for. Restart/reorg/indexer-stale paths are exercised.
- Then run a tiny, operator-signed Base mainnet proof with one eligible token: verified contract source/address manifest, transaction receipts, indexer rows, admin and public UI, balances, order fill/cancel and post-expiry redemption reconcile. Use encrypted Foundry keystore or wallet signing; never paste a private key into shell history, repo or logs. Publish no production liquidity promise until real quotes exist.
- The original Risk Split remains accessible and documented throughout. New fixed-dollar YES tickets, arbitrary payoff compilers, Aave collateral yield, perps and fully permissionless expiries are **research**, not part of this first release.
